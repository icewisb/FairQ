## 执行规则

公平性按 Redis 成功领取的线性执行顺序验证，不按网络返回/Handler完成排序。使用受控串行领取验证精确滑动窗口；多进程竞争另验证无重复和全量守恒，必要时在测试环境采集执行顺序，不能向生产增加序号Key。

故障用例核对每个稳定ID的可解释终态/现存任务/异常证据，不能只检查总数。Inspector在线扫描不是事务快照，报告候选异常后重读确认；全量精确不变量检查在静止fixture或停写窗口进行。

单元测试用Clock/RNG验证调度；Lua测试以Redis TIME为准。长稳不可缩短后冒充通过，硬件不满足阈值要记录失败并取得设计批准，不能静默改标准。基础测试环境不可用时明确失败，不使用t.Skip掩盖必需项。
